# Source Model

`ai/**` is the source of truth. Native tool files outside `ai/**` are generated and should not be edited directly.

## Core Directories

- `ai/config.yml`: enabled platform ids and project metadata.
- `ai/platforms/<platform>.yml`: platform plugin id, owned generated paths, limits, and requirements.
- `ai/targets/<platform>.yml`: assembled markdown outputs for a platform.
- `ai/fragments/*.md`: reusable instruction content with YAML metadata and variants.
- `ai/skills/<name>/skill.yml`: skill metadata, platform targets, sources, resources, and platform-specific metadata.
- `ai/skills/<name>/instructions.md`: generated `SKILL.md` body.
- `ai/skills/<name>/references/**`: copied into generated skill packages for progressive loading.
- `ai/references/migrated/**`: legacy source material preserved for audit, not generated by default.
- `tools/ai/**`: compiler, renderer, validation, plugins, and tests.
- `scripts/ai`: CLI entrypoint.

## Data Flow

1. `tools.ai.core.load_model` reads `ai/config.yml`, scopes, fragments, platforms, targets, and skills.
2. `tools.ai.validate.instantiate_plugins` loads enabled platform plugins.
3. Each plugin renders `GeneratedFile` values from targets and skills.
4. `scripts/ai generate` writes generated outputs.
5. `scripts/ai generate --check` compares expected generated outputs with committed files and reports stale or extra owned files.

## Generated Ownership

Ownership is path-based:

- `owned.exact_files` protects individual generated files.
- `owned.exact_dirs` protects entire generated directories.

If a generated directory is owned, every committed file inside it must be generated. Keep manual files outside owned generated paths.

## Traceability

Generated markdown uses an HTML trace header. Generated YAML uses comment headers. Generated skill directories include `.ai-manifest.json`. These traces are part of the contract and should stay stable enough for reviewers to identify source files.
