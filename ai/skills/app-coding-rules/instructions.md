# App Coding Rules

## Workflow

1. Inspect nearby code and tests before changing behavior.

2. Follow existing local patterns unless the requested change requires a different structure.

3. Keep changes scoped to the requested behavior and the smallest practical set of files.

4. Read `references/test-writing.md` before creating or updating tests.

5. Validate changed code with the narrowest useful test and analyzer commands for the touched files.

6. For PDF changes, verify the generated document behavior through focused tests or a local preview/build when practical.
