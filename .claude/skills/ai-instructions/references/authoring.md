# Authoring AI Data

Use source-first edits and let the compiler produce native files.

## Add Or Update A Fragment

1. Edit or create `ai/fragments/<name>.md`.
2. Include YAML frontmatter with `id`, `kind`, `title`, `owner`, `status`, and `targets`.
3. Add `# Standard` for full-detail targets.
4. Add `# Compressed` when the fragment is used by limited-context targets.
5. Reference the fragment from `ai/targets/<platform>.yml`.

Use fragments for always-on project guidance, review guidance, architecture rules, and other reusable instruction blocks.

## Add Or Update A Target Output

1. Edit `ai/targets/<platform>.yml`.
2. Add an output with `id`, `target`, `scope`, `title`, and `include`.
3. Add platform frontmatter only when the native platform needs it.
4. Keep budgeted outputs on compressed fragments.
5. Add tests when the output is required or has a platform-specific contract.

## Add Or Update A Skill

1. Create or edit `ai/skills/<name>/skill.yml`.
2. Use a lowercase hyphenated `name` that matches the generated folder name.
3. Write a high-signal `description`; agents use it for skill selection.
4. Put core workflow in `instructions.md`.
5. Put detailed or optional material in `references/**`.
6. Add scripts only when deterministic execution is worth the maintenance cost.
7. Add platform ids under `targets`.
8. Add platform metadata blocks only when needed, such as `openai` or `claude`.

Prefer concise skill bodies. A good generated `SKILL.md` tells the agent what to do next and when to read references.

## Add References

References should be loaded only when needed. Keep them one level below the skill when possible:

```text
ai/skills/<name>/
  instructions.md
  references/
    topic.md
```

Mention each reference in `instructions.md` with when to read it. Register each file in `skill.yml` under `resources.references`; otherwise it will not be copied into generated skill packages.

## Validation Checklist

- `scripts/ai validate`
- `scripts/ai generate --check`
- `python3 -m unittest tools.ai.tests.test_compiler`
- `scripts/ai list` when reviewing output provenance
- `scripts/ai explain <generated-path>` when checking a generated file source
