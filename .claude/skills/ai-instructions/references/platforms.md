# Platform Support

Add or change a platform in small, verifiable slices.

## Add a Platform

1. Add `ai/platforms/<platform>.yml` with:
   - `id`
   - `display_name`
   - `plugin`
   - `owned.exact_files` or `owned.exact_dirs`
   - limits and requirements when the platform has file shape constraints

2. Add `ai/targets/<platform>.yml` if the platform renders assembled markdown outputs.

3. Implement `tools/ai/plugins/<platform>.py`.

4. Register the plugin in `tools/ai/plugins/__init__.py`.

5. Add the platform id to `enabled_platforms` in `ai/config.yml`.

6. Add tests in `tools/ai/tests/test_compiler.py` for required outputs, limits, and generated file shape.

7. Run `scripts/ai generate`, then validation.

## Platform Plugin Pattern

Plugins usually implement:

- `render(model)`: returns all `GeneratedFile` values for that platform.
- `validate_source(model)`: catches missing source files, bad metadata, or platform-specific source requirements.
- `validate_output(model, outputs)`: catches missing outputs, wrong paths, frontmatter mistakes, or size limits.

Use existing plugins as templates:

- `agents.py`: single assembled root markdown output.
- `cursor.py`: assembled rules plus generated skill packages.
- `codex_skills.py`: generated skill packages plus OpenAI metadata.
- `claude.py`: assembled root memory plus generated skill packages.
- `copilot_review.py`: frontmatter and character-budget enforcement.

## Skills On Platforms

When a platform supports skills, render from `ai/skills/<name>` instead of duplicating instructions manually. A skill should opt into a platform by listing that platform in `targets`.

Generated skill directory conventions:

- Codex: `.agents/skills/<name>/`
- Cursor: `.cursor/skills/<name>/`
- Claude: `.claude/skills/<name>/`

If a platform requires additional metadata, keep it in a platform-specific block in `skill.yml`.
